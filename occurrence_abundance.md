# Worked example 1: bacterial occurrence and abundance

This example uses a single-visit survey with many taxa and no environmental data. It shows what happens when there are more features than samples (n : p < 1) and the aim is to predict at new sites.

**Data:** [`occurrence_abundance_example.xlsx`](occurrence_abundance_example.xlsx)
**App:** [Biodiversity Forecasting Decision Framework](https://your-app-name.streamlit.app) <!-- replace with your app URL -->

> The data are **simulated**. The water bodies are fictional, and the read counts were generated by a statistical model to look realistic. They do not describe any real site.

---

## The question

> *Can the rest of the bacterial community predict whether* Microcystis *(a bloom-forming cyanobacterium) is present at lakes that have not been surveyed?*

This is a **species occurrence** question, predicted at **new sites in the same regions**, from a **single survey** with no time series.

## The data

There are 131 sites in 35 fictional water bodies, each sampled once in summer 2025, with read counts for 329 freshwater bacterial genera. As in real eDNA tables, most genera are absent from most sites: about 65% of the cells are zero.

| Sheet | What it holds |
|---|---|
| `abundance` | Read counts: one row per site, one column per genus |
| `occurrence` | Presence (1) or absence (0), calculated from `abundance` |
| `site_info` | Water body, type, region, habitat (littoral, pelagic, inflow, outflow, sediment), date, total reads and genera detected per site |
| `genera` | Each genus, its broad taxonomic group, the number of sites it occurs at and its total reads |
| `app_inputs` | The values to enter in the app, calculated from the data where possible (yellow cells) |

Site codes follow the pattern `region-water body-habitat and number`. For example, `NW-ASHME-LIT01` is the first station, in the littoral zone, at Ashby Mere in the North West.

## Step 1 · Tier 1: problem definition

| App input | Enter | Where it comes from |
|---|---|---|
| Ecological objective | Species occurrence and abundance | Predicting where one genus occurs |
| Response measured as | Occurrence (presence/absence) | Use the `occurrence` sheet |
| Spatial domain | Transfer – new sites in a similar region | Predicting at unsurveyed lakes |
| Number of sites | **131** | Rows in `abundance` |
| Temporal mode | State inference – estimate the current, incompletely observed state | One survey; no forecasting through time |
| Temporal resolution | Months | Not used in the calculation |
| Time points per site | **1** | Each site was sampled once |

The app reports one required capability: **spatial transfer**.

### What the app calculates

| Value | Result | Why |
|---|---|---|
| Effective n | 131 | One sample per site, so every sample counts fully |
| n_eff : p | 0.40 | 131 ÷ 328 |
| Table B1 band | < 1, high-dimensional | More predictors than samples: high overfitting risk |

## Step 3 · Tier 3: method filtering

| Class | Methods | Why |
|---|---|---|
| ✅ Recommended | Bayesian hierarchical models | Share information across sites (spatial transfer); shrinkage priors cope with n : p < 1; robust to noisy detection |
| ⚠️ Use with caution | Regularised regression, PLS regression | Only partly support transfer to new sites; sensitive to noisy data |
| ⚠️ Use with caution | Random forest | Only partly supports transfer to new sites |
| ⚠️ Use with caution | Process-based models, SVM | Below their preferred n : p band |
| ❌ Excluded | GLM, GAM, gradient boosting, neural networks, deep learning | Need n : p of at least 1–5 or more |
| ❌ Excluded | Ordination, nMDS/PERMANOVA | Model whole communities, not one genus |
| ❌ Excluded | All time-series methods | Only one time point per site |

## Step 4 · Tier 4: evaluation and reporting

- **Validation:** spatial-block cross-validation, holding out groups of nearby sites. Use `Water body` in `site_info` as the grouping, so stations from the same lake are never split between training and test sets. Because n : p < 1, tune settings inside the training folds only (a nested design) and use permutation tests.
- **Metrics:** AUC for discrimination, a calibration plot, the Brier score, and skill against an intercept-only model.
- **Ecological plausibility:** flagged, because data-driven methods are retained.
- **Taxonomic resolution:** a warning, because no reads are assigned to species.

## Try changing one input

| Change | What happens |
|---|---|
| Computing → **Limited (laptop)** | Bayesian hierarchical models drop out, leaving only methods to use with caution |
| Spatial domain → **Interpolation – same sites** | Random forest joins Bayesian hierarchical models as **recommended**; validation switches to nested cross-validation |
| p → **20** (if you had 20 environmental predictors instead of the community) | n : p rises to 6.6 (band 5–10); GLM, GAM, gradient boosting and shallow neural networks become usable with caution |
| Objective → **Community composition**, p → **329** | Ordination, nMDS/PERMANOVA and PLS move to caution; nothing is recommended |

Results shown are from app version 4.0.
