# Tutorial 4: lake bacterial communities and nutrient reduction (responses to management)

A seasonal survey with environmental pressure data, used to project how lake bacterial communities respond if phosphorus inputs are halved. It shows how repeated sampling of the same sites reduces the effective sample size, and how a strict interpretability requirement narrows the options.

**Data:** [`tutorial4_environmental_pressures.xlsx`](tutorial4_environmental_pressures.xlsx) · **Shortcut:** in the app, open the **Tutorials** tab and click **Load Tutorial 4**.

> The data are **simulated**. Water bodies are fictional; counts and measurements were generated by a statistical model.

## The question

> *If phosphorus inputs to these catchments were halved, how would the lake bacterial communities respond?*

**Context:** nutrient reduction is a standard programme of measures for lakes under the **Water Framework Directive**.

## The data

| | |
|---|---|
| Design | **40 sites** in 35 fictional water bodies, each sampled in four seasons of 2025 (**160 samples**) |
| Measurements | Read counts for **150 bacterial genera** (genus level) and **20 environmental variables**: 13 measured each visit (temperature, pH, oxygen, conductivity, phosphorus, nitrogen, chlorophyll a, turbidity, organic carbon, rainfall) and 7 site characteristics (catchment soil phosphate, land use, distance to wastewater works, depth, altitude) |
| Missing data | About 10% of laboratory measurements (about **5%** of all environmental values) |
| Built-in patterns | Cyanobacteria increase with phosphorus and summer temperature; gut-associated genera increase near wastewater discharges |
| Sheets | `data`, `variables`, `app_inputs` |

## Step 1 · Tier 1: problem definition

| App input | Enter | Why |
|---|---|---|
| Ecological objective | Responses to environmental change or management interventions | Effect of a management measure |
| Spatial domain | Interpolation – same sites or conditions as the data | The same 40 sites |
| Number of sites (*n*_sites) | **40** | Different codes in the `Site` column |
| Temporal mode | Long-term scenario projection | Response under a future nutrient scenario |
| Time points per site (*m*) | **4** | Four seasons |

Required capabilities: **extrapolation, representation of temporal dynamics, process knowledge, uncertainty propagation**.

## Step 2 · Tier 2: data and analytical constraints

| App input | Enter | Why |
|---|---|---|
| Number of features (*p*) | **20** | The environmental predictors |
| Correlation between samples (ρ) | Moderate (ρ ≈ 0.5) | Seasonal samples from one lake are related but change with season |
| Level of identification | Genus | |
| Missing values (%) | **5** | Calculated in `app_inputs` |
| Interpretability | High (regulatory / policy) | Results would inform catchment management |
| Computing | Moderate (workstation) | |

**What the app calculates:** each site's four samples are worth 1.94 independent samples, so *n*_eff = 40 × 1.94 × 0.95 = **73.7**; *n*:*p* = **3.7** (band 1–5). The sheet has 160 rows, but the data are worth about 74 independent samples.

## Step 3 · Tier 3: method filtering and prioritisation

| Class | Methods | Why |
|---|---|---|
| ✅ Recommended | Process-based models | Represent nutrient–plankton–microbial processes; suited to a future scenario |
| ⚠️ Cautious use | Bayesian hierarchical models, data assimilation | Partial support for extrapolation and process knowledge |
| ⚠️ Cautious use | State-space models, ARIMA, dynamic occupancy models, regularised VAR | Represent change through time but cannot extrapolate alone; four time points is short for most |
| ⚠️ Cautious use | Ensemble forecasting | Below its preferred *n*:*p* band |
| ❌ Excluded | SVM | Black box, excluded by the High interpretability requirement |
| ❌ Excluded | GLM, GAM, neural networks, deep learning | Need a higher *n*:*p* |
| ❌ Excluded | Hybrid models, PINNs | Need HPC-level computing |

## Step 4 · Tier 4: forecast evaluation, uncertainty and reporting

- **Validation:** forward-chaining validation (train on earlier seasons, test on later ones). With four seasons this is a weak test; plan follow-up sampling.
- **Metrics:** error in predicted change, RMSE and MAE, CRPS, prediction-interval coverage, skill against persistence.
- **Uncertainty:** keep the future nutrient scenario separate from parameter and model uncertainty.
- **Plausibility:** flagged as a priority, because the forecast goes beyond observed conditions.
- **Taxonomic resolution:** note that taxa are identified to genus level.

## Try changing one input

| Change | Result |
|---|---|
| Objective → **Community composition**, *p* → **170** (150 genera + 20 predictors) | *n*:*p* falls to 0.43 (band < 1); nothing is recommended |
| Spatial domain → **Transfer – new sites** | Bayesian hierarchical models join process-based models as recommended |
| Temporal mode → **Near-term iterative** | Time-series methods move up the list, but four time points is too few for any to be recommended |
| Missing values → **25%** | *n*_eff falls to 58 and *n*:*p* to 2.9; the classes stay the same |
