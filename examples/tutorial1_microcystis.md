# Tutorial 1: *Microcystis* in lakes (species occurrence)

A single survey with many taxa and no environmental data, used to predict where a bloom-forming cyanobacterium occurs at lakes that have not been surveyed. It shows what happens when there are more features than samples (*n*:*p* < 1).

**Data:** [`tutorial1_microcystis.xlsx`](tutorial1_microcystis.xlsx) · **Shortcut:** in the app, open the **Tutorials** tab and click **Load Tutorial 1**.

> The data are **simulated**. Water bodies are fictional; read counts were generated by a statistical model.

## The question

> *Where is* Microcystis *likely to occur in lakes we haven't surveyed?*

**Context:** phytoplankton, including bloom-forming cyanobacteria, is a biological quality element for lakes under the **Water Framework Directive**. Forecasts would support regulatory decisions, so explainable methods are needed.

## The data

| | |
|---|---|
| Design | One summer survey (2025) of **131 sites** in 35 fictional English lakes, meres, tarns, reservoirs, broads and ponds; 3–5 stations per water body (littoral, pelagic, inflow, outflow, sediment) |
| Measurements | eDNA metabarcoding read counts for **329 freshwater bacterial genera**, identified to genus level; about 65% of cells are zero |
| Sheets | `abundance`, `occurrence` (presence/absence by formula), `site_info`, `genera`, `app_inputs` |

## Step 1 · Tier 1: problem definition

| App input | Enter | Why |
|---|---|---|
| Ecological objective | Species occurrence and abundance | Predicting where one genus occurs |
| Response measured as | Occurrence (presence/absence) | Use the `occurrence` sheet |
| Spatial domain | Transfer – new sites in a similar region | Unsurveyed lakes in the same regions |
| Number of sites (*n*_sites) | **131** | Rows in `abundance` |
| Temporal mode | State inference | One survey; no forecast through time |
| Time points per site (*m*) | **1** | Each site sampled once |

Required capability: **spatial transferability**.

## Step 2 · Tier 2: data and analytical constraints

| App input | Enter | Why |
|---|---|---|
| Number of features (*p*) | **328** | The other genera predict *Microcystis* |
| Correlation between samples (ρ) | (greyed out) | One time point per site |
| Level of identification | Genus | |
| Missing values (%) | 0 | Zeros are absences, not missing values |
| High noise / detection uncertainty | Tick | eDNA detection is imperfect |
| Interpretability | High (regulatory / policy) | Regulatory use |
| Computing | Moderate (workstation) | |

**What the app calculates:** *n*_eff = 131; *n*:*p* = 131 ÷ 328 = **0.40** (Table B1 band < 1, high overfitting risk).

## Step 3 · Tier 3: method filtering and prioritisation

| Class | Methods | Why |
|---|---|---|
| ✅ Recommended | Bayesian hierarchical models | Share information across sites; shrinkage priors handle *n*:*p* < 1; robust to noisy detection |
| ⚠️ Cautious use | Regularised regression, PLS regression, random forest | Only partly support transfer to new sites; regression methods are sensitive to noisy data |
| ⚠️ Cautious use | Process-based models | Below their preferred *n*:*p* band |
| ❌ Excluded | SVM | Black box, excluded by the High interpretability requirement |
| ❌ Excluded | GLM, GAM, gradient boosting, neural networks, deep learning | Need a higher *n*:*p* |
| ❌ Excluded | Time-series methods | State inference does not forecast through time |

## Step 4 · Tier 4: forecast evaluation, uncertainty and reporting

- **Validation:** spatial-block cross-validation; group stations by `Water body` so a lake is never split between training and test data. Because *n*:*p* < 1, tune inside the training folds (nested design) and use permutation tests.
- **Metrics:** AUC, calibration plot, Brier score, skill against an intercept-only model.
- **Plausibility:** flagged, because data-driven methods are retained.
- **Taxonomic resolution:** note that taxa are identified to genus level.

## Try changing one input

| Change | Result |
|---|---|
| Interpretability → **Medium** | SVM returns as cautious use |
| Computing → **Limited (laptop)** | Bayesian hierarchical models drop out; nothing is recommended |
| Spatial domain → **Interpolation** | Random forest joins the recommended list; validation becomes nested cross-validation |
| *p* → **20** (environmental predictors instead of the community) | *n*:*p* = 6.6; GLM, GAM and gradient boosting become cautious use |
